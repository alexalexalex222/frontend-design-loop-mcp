# Candidate source and evidence

Use one implementation for a clear repair. Explore alternatives when different
approaches could materially improve the user's task or resolve a design question.
Each alternative needs an intent, audience rationale, source checkpoint, relevant
checks, and labeled screenshots. Isolation and editing belong to the host agent;
this toolkit does not create worktrees or restore source.

Record baseline, candidate, and preferred states separately. `capture_screenshots`
creates a fresh directory each time, so later captures do not overwrite earlier
images. `source_revision` is an unverified caller label: bind the evidence to your
actual source checkpoint yourself. Preserve the best source state before refining.
Keep worker edits disjoint when delegation is authorized. Compare candidates on
consistent viewport sizes, content, tasks, and practical constraints.
